# Инструкция по деплою на Railway

## Шаги для деплоя

### 1. Подготовка изменений

Убедитесь, что все изменения закоммичены:

```bash
# Добавить все изменения
git add .

# Создать коммит
git commit -m "Fix: Support NULL year_to for ongoing models (Dodge Journey fix)"

# Запушить в main ветку
git push origin main
```

### 2. Railway автоматически задеплоит

После push в main ветку Railway автоматически:
- Запустит build процесс (`npm run build`)
- Запустит приложение (`npm start`)
- Проверит health check на `/health`

### 3. ВАЖНО: Выполнить миграцию БД

После деплоя нужно выполнить миграцию в базе данных Railway:

**Вариант 1: Через Railway CLI** (рекомендуется)
```bash
# Установка Railway CLI (если еще не установлен)
npm install -g @railway/cli

# Логин
railway login

# Подключение к проекту
railway link

# Выполнение миграции
railway run psql $DATABASE_URL -f migrations/004_allow_null_year_to.sql
```

**Вариант 2: Через веб-интерфейс Railway**
1. Откройте Railway Dashboard
2. Выберите ваш проект
3. Откройте PostgreSQL сервис
4. Перейдите в "Query" tab
5. Выполните SQL:
```sql
ALTER TABLE catalog_hit
  ALTER COLUMN year_to DROP NOT NULL;
```

### 4. Проверка работы

После деплоя и миграции проверьте:

1. Health check:
```bash
curl https://your-app.railway.app/health
```

2. Поиск Dodge Journey 2013:
```bash
curl -X POST https://your-app.railway.app/api/lookup \
  -H "Content-Type: application/json" \
  -d '{"make": "Dodge", "model": "Journey", "year": 2013}'
```

### 5. Переменные окружения

Убедитесь, что в Railway настроены:
- `DATABASE_URL` - автоматически создается при добавлении PostgreSQL
- `PORT` - опционально (по умолчанию 8080)
- `NODE_ENV` - опционально (можно установить `production`)

### 6. Мониторинг

После деплоя проверьте:
- Логи в Railway Dashboard → Deployments → Latest → Logs
- Метрики в Railway Dashboard → Metrics
- Health check endpoint должен возвращать `{"status":"ok","db":"ok"}`
